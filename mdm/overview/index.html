Mobile Device Management (MDM)

Overview​

A Mobile Device Management (MDM) solution, also called an Enterprise Mobility Management (EMM) solution, lets administrators enroll, configure, secure, and update a fleet of devices from a central web console. Instead of setting up each device by hand, an administrator defines policies once and the MDM pushes them to every enrolled device.

An MDM is typically used to:

  • Enroll devices in Android Enterprise as fully managed (device owner) devices
  • Install, update, and remove applications through managed Google Play or the MDM's own enterprise app catalog
  • Apply device policies such as passcodes, restrictions, and Wi-Fi networks
  • Configure Datalogic-specific settings, including scanner settings, through OEMConfig
  • Apply Scan2Deploy profiles without scanning a barcode
  • Deploy firmware and Espresso package updates. Espresso is the Datalogic package of device-specific drivers and APIs that runs on top of the Android firmware.

Datalogic devices work with any Android Enterprise compatible MDM, including SOTI MobiControl, Microsoft Intune, SureMDM, Workspace ONE, and many others.

Differences between MDMs​

Every Android Enterprise MDM supports the core features: enrollment, managed Google Play apps, device policies, and OEMConfig. Beyond that, MDMs are not created equal. Some features are missing or work differently, and the same feature often has a different name in each MDM. Where an MDM doesn't support a feature, these docs describe a workaround, such as hosting files on Azure Blob Storage, or launching Scan2Deploy through OEMConfig on Microsoft Intune.
