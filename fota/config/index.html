Arrow FOTA Settings

Overview​

The following sections detail the various configuration settings of the FOTA service. These screens can be reached from the main Arrow FOTA Settings screen.

Network and License Settings​

Tapping the Network and License group presents a screen which controls the connections to the FOTA server. The following settings are available:

SettingDescription
Server
Transport modeSelects which server will be used for OTA downloads.
Firmware serverThis is the IP address of the Arrow FOTA Proxy server. It is only used when the Transport mode specifies use of the proxy server.
Licenses
Shield LicenseThis is the Shield license key used by the FOTA service to authorize firmware updates on the device. A valid key is required for FOTA operation regardless of which server is used.
Arrow FOTA LicenseThis is the license used to access the Arrow FOTA cloud server. A valid key is required for FOTA operation only when the Transport mode specifies use of the cloud server.
Restriction
Allow cellular downloadsAllows downloads to be performed over a cellular network connection.

Schedule Settings​

Tapping the Schedule group presents a screen which defines when the FOTA service is allowed to automatically check for updates. The following settings are available:

SettingDescription
Frequency
Polling frequencyWithin each polling window (described below), this is the time period between checking for updates.
Schedule rules
Add polling windowTap this to add a new polling window. See the next section for details.

Polling Windows​

The FOTA service is only allowed to automatically check for updates during specific times, called polling windows. The bottom of the screen displays a list of all defined polling windows. It is valid to not define any polling windows, but these are required for automatic updates to function.

Each polling window defines the days and times when the FOTA service is allowed to perform automatic updates. It is intended that these windows specify times when the device can tolerate the use of any additional resources required by the update (such as outside of a work shift). Multiple windows may be defined, which allows for different schedules depending on the day of the week and/or time of year.

Within a polling window, the service will periodically check for updates. The frequency of these checks is determined by the Polling frequency setting.

Add a Polling Window​

When you add a polling window, a dialog is displayed with controls to specify the days and times of the window.

SettingDescription
Active daysAllowed days to check for updates. If any days are selected, polling may take place on a weekly basis. When no days are selected, polling may take place during the range of dates.
Start dateFirst date of the polling window. This is valid only if no Active days are selected.
End dateLast date of the polling window. This is valid only if no Active days are selected.
Start timeEarliest time during the specified days for the polling window.
End timeLatest time during the specified days for the polling window. If the end time is earlier than the start time, it refers to a time on the following day. For example, times of 11:00 PM and 1:00 AM specify a time frame that starts at 11:00 at night and continues for two hours until 1:00 in the morning the next day.

Edit a Polling Window​

To edit a polling window, tap the Edit icon () for its list entry. You will see the same dialog as when adding a polling window. Make any desired changes and tap Save to commit the changes.

Delete a Polling Window​

To remove a polling window from the list, tap the Delete icon () for its list entry. You will be asked to confirm the deletion.

Policy Settings​

Tapping the Policy group presents a screen which determines how the FOTA service selects firmware and Espresso versions when checking for updates. The following settings are available:

SettingDescription
Firmware
Firmware selectionSpecifies which firmware version will be selected for updates.
  • Latest: The latest version available on the selected update channel will be used
  • Specific version: Only the version specified by Target firmware version will be used
Target firmware versionWhen a specific firmware version is selected, this is the version string to use. Example: 3.27.018
Update policyDetermines whether smaller incremental update files may be used when updating the firmware.
  • Prefer incremental updates: Attempt to perform an update using an incremental update image, if one is available
  • Incremental-only updates: Only incremental update images will be used
  • Full updates only: Only full images will be used
Allow OS updatesPermits an update which involves an upgrade of the Android OS version.
Allow maintenance release updatesPermits an update which is includes non-security content (new features).
Update channelLimits updates to the specified channel(s).
  • Public: Updates which are fully tested and intended for general use
  • Beta: Updates which are partially tested; intended for early access to new features and/or bug fixes
  • Any: Updates are allowed from any channel
Update delayThe number of days after an update is released before it is allowed to be used. This can be used to delay updating to the latest firmware upon its release.
Espresso
Espresso update modeSpecifies which Espresso package is selected for update.
  • Original release: Only the version originally specified by the firmware will be used
  • Latest compatible: The latest version compatible with the firmware will be used
  • Specific version: Only the version specified by Target Espresso version will be used
Target Espresso versionWhen a specific Espresso version is selected, this is the version string to use. Example: 3.27.018
Restriction
Install only while chargingAllows updates when the device is not attached to a charging power supply.

Postponement Settings​

Tapping the Postponement group presents a screen which controls the display of any user confirmation dialogs when the FOTA service initiates an update. The following settings are available:

SettingDescription
User Prompts
Zero touch updatesAllows updates to be performed without user interaction. When disabled, a dialog will be presented for the user to confirm the update before it begins.
User confirmation timeoutSpecifies how long a confirmation dialog will wait for a user response before proceeding with an update automatically.
Reminder Settings
Allow remindersAllow the user to dismiss the confirmation dialog and be reminded at a later time.
Reminder delaySpecifies how long to wait between confirmation dialogs.
Maximum remindersSpecifies the number of confirmation dialogs that are displayed before an update is performed automatically.
